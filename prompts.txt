I want you to create a project called "AI already did it". It is a web-based application.

## What we are building
A repository / free marketplace for applications written by LLMs. Humans and LLM agents can search previously LLM-generated applications by keyword or semantically and download them freely.

## Purpose
1. Prevent the same applications from being generated over and over by LLMs, wasting the world's compute and energy resources.
2. Save users from burning their own tokens (and money) on applications that have already been built.

## Three golden rules for every uploaded app
1. Must be open source, so another LLM can modify the source code — which burns far fewer tokens than generating from scratch. Enforce this: a mandatory SPDX license field, plus a check that the repository/archive actually contains a LICENSE file matching it.
2. Must be installable on specific, declared platforms.
3. Must be free.

## Mandatory upload requirements
An app submission cannot be completed unless ALL of the following are provided:
1. Source code — either a public Git repository URL (GitHub/GitLab) or a source archive upload. Repository import is the primary path: fetch README, LICENSE, primary language, stars, releases and changelog automatically. Zip upload is the fallback.
2. At least one working, ready-to-run install/binary file per declared platform (e.g. .exe, .msi, .deb, .rpm, .dmg, .apk, .AppImage, Docker image reference, or a runnable web bundle).
3. At least one screenshot (enforce a minimum; recommend 3+).
These exist to make life easier for other users, so validate them strictly on both client and server.

## Additional required metadata per app
- Category (hierarchical), name, short and long description, tags.
- Platforms: structured list (Windows / Linux / macOS / Web / Android / iOS / Docker / CLI), each with its own install file.
- Versions: every version has its own files, changelog and release date.
- Generating LLM: model name and version (e.g. Claude Opus 4.x, GPT-5, Gemini 2.5), plus the original prompt(s) used to generate the app, so others can edit the prompt and quickly produce their own variant.
- Lineage: optional "derived from / fork of" link to another app in the store.
- License (SPDX).

## Duplicate detection at upload time
While the uploader types the description, run a semantic search against existing apps. If similarity is above a threshold, show "This looks ~85% similar to X — would you rather contribute to it or declare yours as a fork?" This directly serves the project's purpose.

## API for LLM agents (key differentiator)
- A public REST API for search and download so agents (Claude Code, etc.) can query the store before generating anything.
- An MCP server exposing tools such as `search_apps`, `get_app`, `list_categories`, `download_app`. The intended flow: an agent is asked to build something → it first asks this store "has someone already done this?".
- API keys and rate limiting for these endpoints.

## User interface
- Storefront / showcase: description, screenshots, rating, number of ratings, download count, platforms, license, generating model.
- Search: category-first filtering like sahibinden.com, then refine by platform, license, model, rating, tags. Keyword and semantic search combined.
- Login / signup with email and Google (OAuth). Registration is optional — anonymous users can search and download everything.
- Ratings out of 100 + short review + a "worked / didn't work on version X" flag. Only users who actually downloaded the app can rate it.
- User dashboard: my uploaded apps, my ratings/reviews, download history, favorites/collections, "notify me on new versions of this app", API keys for the agent API.
- Report abuse button on every app.
- Homepage "savings counter": estimated tokens/cost saved thanks to the store (downloads × estimated generation cost of the app). Make the mission visible.
- TR/EN i18n. SEO: app detail pages must be server-rendered or prerendered.

## Global admin panel
I am the site administrator, so build a very comprehensive admin panel: moderation queue (new uploads require approval), reports handling, user management, category/tag management, license/platform lists, featured apps, statistics (downloads, searches, savings, top apps), audit log, system health.

## Security
- Uploaded archives and binaries go through a basic scan (ClamAV) before publication.
- JWT + refresh tokens, Google OAuth, rate limiting on all public endpoints.

## Technology stack
- Database: PostgreSQL.
- Semantic search: evaluate PostgreSQL + pgvector (+ tsvector for full text) first, since it keeps everything in one database and is operationally much lighter. Use OpenSearch only if you can justify it; explain your choice.
- Object storage for screenshots and install files: S3-compatible (MinIO locally).
- Backend:
  * Create a `src-backend` directory.
  * ASP.NET Core 10 Web API.
- Frontend:
  * Create a `src-frontend` directory.
  * Vue 3 + TypeScript + Element Plus.
- docker-compose that brings up the whole stack (API, frontend, PostgreSQL, MinIO, ClamAV, MCP server) with a single command.
